    建议的最小落地路径

    每一步独立验收，失败时不把问题带进下一步。下列顺序是工程建议，不是采购清单。

    01 / 当前已完成

    纯软件交互与协议

    确认五开关功能、光效优先级、异常文案和状态回执，无需硬件。

    02 / 沿用现有电脑

    Windows 宿主适配器

    分别实现并实测静音、熄屏、投影、重启、状态回读和权限；小爱接口先做可行性验证。

    03 / 工作台电路

    开关、主控与 LED

    锁定准确板型和开关资料，验证 15 个位置、去抖、USB 数据、供电和光效，再设计外壳。

    04 / 独立安全验收

    语音、隐私与电源

    验证麦克风物理隔离、盒子断电与恢复路径，最后进行结构、电气和长时间运行测试。

    能力缺口与最小验收

    “已模拟”只代表页面状态机可体验，不代表器件兼容。真实适配器和验收记录仍全部缺失。

    模块接入前必须补齐最低验收证据
    主控与固件统一主控路线，记录准确板型、硬件修订、固件版本、官方引脚图；建立可编译固件与版本标识。固件编译记录、启动日志、每个输入输出的逐项实测。
    五个三位开关开关真实接触形式、引脚和有效电平；输入拓扑、消抖、非法组合与上电读取策略。15 个位置及快速拨动测试；无常驻误触发、无卡键误判。
    Type-C 与通信供电和数据角色、完整接口原理图、线缆要求、电流预算、静电与过流保护；选择串口或其他已验证协议。插拔、重连、异常数据和长时间通信记录，不能只证明“能供电”。
    顶部 LED实际灯珠数量与驱动、电源预算、导光结构、非阻塞动画和光效优先级。白光、蓝呼吸、紫双闪、红快闪、红常亮（麦克风禁用）与红闪烁 1 秒周期（异常）的时序与温升实测。
    小爱同学可支持的控制入口和版本范围。旧稿中的 COM 接口示例没有官方资料或实测支持，不能直接采用。启动、关闭、恢复、异常退出和版本兼容性测试；若无受支持接口则更换实现路线。
    麦克风隐私明确物理断开的是供电还是数据、继电器与麦克风实际电路、默认安全状态和状态回读。仪器测量与录音链路双重验证；页面或系统“静音”不能替代物理隔离。
    Windows 控制本地宿主程序、命令白名单、权限、状态回读、超时、重连与结果关联；重启需防误触策略。每个 Windows 版本分别验证静音、熄屏、恢复、投影和重启，不以外壳脚本示例代替验收。
    盒子电源下位关闭后切断哪一路、主控是否仍运行、如何检测回中位并重新上电；不得把模拟开关当作断电设计。断电、恢复、反复切换与异常上电测试，且不影响电脑供电和数据安全。
    结构与生产原理图、PCB、Gerber、结构图、装配工艺、散热、应力释放和测试夹具。样机装配检查、48 小时运行计划和逐项检测报告；认证需另由合格机构确认。

    手册中需要先修正的冲突与未证实项

    以下结论来自两份用户提供材料的交叉核对，不是对器件或服务的在线认证。

    主控路线不统一

    开发沟通同时出现 Arduino UNO、Raspberry Pi 与 Leonardo，V2.1 BOM 写 Leonardo R3。旧稿的 15 路 ADC 示例、USB HID 示例和语音接线不能直接拼成可制造方案。

    上电默认中位只是期望

    机械开关会保持实际位置。真实固件必须在上电时读取位置并决定是否需要首次同步，不能假定“开机默认都在中位”。本原型仅为演示将重置状态设为中位。

    二号下位规则存在版本差异

    D-04（2026-11-18）已裁决红色双语义：红色常亮＝麦克风禁用，红色闪烁（1 秒周期）＝异常。本原型已同步实现；配套程序与日志仍须显示异常的具体原因。

    示例固件不能直接烧录

    手册代码包含未完成片段与语法问题，且缺少完整引脚、状态机、去抖、通信、错误处理和测试工程。应重建可编译固件，而不是照抄片段。

    认证文字不等于证书

    V2.1 写有 FCC、CE-LVD、RoHS 表述，但材料中没有证书、报告编号、适用型号或测试范围。本交付不把它们视为已认证。

    成本算术需要重算

    按 V2.1 BOM 单价直接相加为 ¥380.80，含 ¥15 包装为 ¥395.80，与手册 ¥365.40 不一致。按手册自己的 50 台公式计算为 ¥25,554.00，并非 ¥28,894.00；所有单价仍未询价。

    真实接入合同

    无论最后选择哪种主控或传输方式，都应保留同一请求身份，并分别确认执行、送达和应用。

    device.task.submit→host.task.accepted→host.task.completed→host.result.deliver→device.result.applied
    状态能说明什么不能说明什么
    submitted / accepted请求进入宿主边界并被接受不能推出执行完成或设备已应用
    completed宿主生成结果及结果哈希不能推出结果已送达设备
    delivered设备收到同一结果不能推出设备已经执行或显示
    applied模拟或真实适配器确认应用同一结果模拟 applied 仍不等于真实硬件验收

    解耦边界说明

    本页演示软件层解耦；下列内容属于硬件与安全约束，刻意不纳入可配置范围。

    1 号麦克风门控

    硬件提案方案 A 由 SW1 两根原始输入线经 74LVC1G11 直接门控麦克风供电，不经过固件。软件改映射无法改变硬件通断，故锁定。

    5 号电源与重启

    逻辑关机要求 RP2040 全时供电以检测回中；重启采用单次边沿 + 武装状态机。二者为安全策略，不随配置改变。

    单任务 busy 锁

    忙碌期间 3/4/5 号请求返回 busy、不排队，避免过期动作，属开发手册 3.3 的首版规则。
